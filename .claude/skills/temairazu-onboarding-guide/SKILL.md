# 手間いらず導入手順書 作成Skill

## このSkillの目的

手間いらず（サイトコントローラー）の乗換導入について、**案件（施設）ごとにカスタマイズした導入手順書**を作成する。
標準の導入手順書Excelは全サイト・全パターン網羅で膨大なため、施設担当者は「自分の施設は結局何をいつやればいいのか」が掴みにくい。このSkillは案件の導入内容から**その施設に必要な作業だけを抜き出し、日付とサイト名が入った具体的な手順書**に落とし込む。

## リファレンスファイル

| ファイル | 内容 | いつ読むか |
|---|---|---|
| `references/master-checklist.md` | 導入前17ステップ+導入当日29ステップの標準フロー（操作パスつき）と、案件によるステップ取捨選択ルール | **手順書作成時は必ず読む** |
| `references/site-requirements.md` | 全連携サイト（OTA約60・BE・一元在庫）の事前接続可否・申請要否/手順・過去予約取得可否・注意事項 | 案件の連携サイトが決まったら、該当サイトの箇所を読む |
| `references/output-template.md` | 施設担当者向け手順書のテンプレート（必須構成） | **手順書作成時は必ず読む** |
| `references/ota-account-settings.md` | 主要OTA（Booking.com/Expedia/Agoda/Trip.com系/Airbnb/楽天/じゃらん/るるぶ/一休）のアカウント設定固有注意 | 案件に該当OTAが含まれる場合 |
| `references/tl-switch-notes.md` | TLリンカーンからの切替特有の注意・予約データ移行ノウハウ（**社内情報を含む** → Step 3の「社内情報の扱い」参照） | 前サイトコントローラーがTLの場合は必ず読む |
| `references/example-output.md` | 完成手順書の実例（TLからの乗換・9サイト・PMSあり案件） | 出力の粒度・トーンに迷ったとき |

## Step 1: 案件情報の収集

手順書作成に必要な情報は以下。ExcelやCSV、メール文面などが渡されていればそこから読み取り、不足分だけ質問する。全部そろわなくても、わかっている範囲で暫定版を作り「未確認事項」として明記する方針でよい（担当者が確認すべきことが可視化されるだけでも価値がある）。

1. **施設名**
2. **導入予定日**（切替時間の指定があればそれも。午前指定は楽天・JALパック等で前倒し期限が発生する）
3. **前サイトコントローラー**（TLリンカーン/ねっぱん/らく通/エアホスト/なし=新規 など。TLの場合は特有の注意あり）
4. **連携予定サイト一覧**（OTA・自社予約システム(BE)・一元在庫サービス）
5. **PMSの有無とPMS名**（連携方式が1way/2wayかも分かれば）
6. **料金設定の方式**（プラン料金/料金グループ/プラングループ。不明なら手順書には3方式併記でよい）

## Step 2: サイト分類と期限の逆算

`site-requirements.md` で案件の各サイトを調べ、次の3軸で分類する:

- **事前接続**: 可（導入前に準備可能）/ 否（当日切替）/ 不明（サイトに要確認）
- **申請**: 申請不要 / 手間いらず事前申請 / 両方申請 / サイト連絡
- **過去予約取得**: 可 / 不可（→導入前に現サイコンから予約データのダウンロードが必要）

### 申請期限早見表（導入日から逆算して具体的日付にする）

| サイト | 期限 |
|---|---|
| 一休.com | 導入希望日の**2営業日前18時**までに手間いらず画面から連動申請 |
| Booking.com / Expedia / Agoda | 明示の期限規定はないが「手間いらず事前申請＋導入当日のサイト管理画面切替」の両方が必要。事前申請は余裕をもって（導入2〜3週間前推奨）と案内する |
| WELBOX / OPTIMA | 導入希望日の**3営業日前**までに手間いらず画面から事前申請 |
| JALパック | **最低5営業日前**までに申請。午前接続希望は時間指定して5営業日前までに営業経由でカスタマーセンターに共有 |
| 楽天トラベル（R-connect） | 当日正午までの申請で15〜17時連携。**午前など時間指定がある場合は前日11:50まで**に楽天管理画面+手間いらず画面の両申請を完了 |
| 楽天グローバルプラットフォーム | R-connect利用が前提。**当日11:50まで**に申請完了 |
| Hostelworld | 連動依頼から営業日5日以内に完了連絡。事前の日時指定不可 |
| D-EDGE | 覚書締結から3〜6営業日。サイト側対応が不定期のため**余裕をもって**申請 |
| JTB（るるぶ） | 連携日決定後すみやかに施設→JTBへ連絡（切替時間まで伝える）+手間いらずCSからもJTBへ連絡 |
| ANA / Trip.com / Trip.com(NEW) | 事前にサイトへ連絡・申請（Trip.comは新旧どちらのシステムか要確認）|
| サイト連絡系（relux・ゆこゆこ・ベネフィット等多数） | リードタイム不定。導入日決定後すぐ連絡するようスケジュール最上流に置く |

期限は**営業日ベース**。土日を除いて逆算し、祝日がありそうな場合は「祝日を挟む場合は前倒し」と注記する。

## Step 3: 手順書の生成

`output-template.md` の構成（1.導入概要 → 2.連携サイト分類表 → 3.逆算スケジュール → 4.導入前チェックリスト → 5.当日チェックリスト → 6.サイト別注意点 → 7.連絡先)に従い、`master-checklist.md` の取捨選択ルールで不要ステップを削って生成する。

品質基準:
- サイト名・日付・PMS名は必ず実名で埋める。「各サイト」「該当サイト」のような一般論のまま残さない
- その施設が使わないサイトの情報は一切載せない（読む量を減らすことが目的）
- 操作は「設定＞予約サイト設定＞…」の画面パス形式で書く
- 各作業にチェックボックス（□）を付ける
- 未確認事項は「⚠ 要確認」として冒頭にまとめる（テンプレートのセクション0）

### 社内情報の扱い（重要）

`tl-switch-notes.md` には社内向けノウハウ（担当者の実名、手間いらず「管理ツール」の操作手順など）が含まれる。**施設担当者に渡す手順書にはこれらをそのまま載せない**こと。施設向けには「手間いらず営業担当・カスタマーセンターへ事前にご相談ください」という形に翻訳し、社内担当者向けに手順書を作る場合のみ原文の詳細を使う。どちら向けの文書かが不明なら施設向けとして扱う。

### 判断に迷ったら

リファレンスに明記されていない運用（例: 事前接続済みサイトを当日の売止対象に含めるか、切替時間帯ごとの細かい段取り）は、**推測で断定せず「⚠ 要確認」に落とす**。手順書の価値は正確さと、確認すべきことが漏れなく可視化されていることにある。
なお連絡先セクションの電話番号等の実データはリファレンスにないため、プレースホルダ（「ご担当営業にご確認ください」等）とし、ユーザーが知っていれば埋めてもらう。

出力形式: まずMarkdownで作成して内容を確認してもらい、依頼に応じてExcel（xlsx Skill）/ Word（docx Skill）/ HTMLに変換する。施設に渡す最終版はdocxまたはxlsx推奨。

## Step 4: セルフチェック

生成後、以下を確認してから納品する:

- [ ] 連携サイト全部が分類表に載っているか（漏れがちなのはBE・一元在庫サービス）
- [ ] 申請期限のあるサイトすべてがスケジュール表に日付入りで載っているか
- [ ] 過去予約取得「不可」サイトについて、事前の予約データダウンロード指示があるか
- [ ] PMSなし案件にPMS手順が残っていないか（逆にPMSあり案件で16→20→出力する戻しの流れが入っているか）
- [ ] 前サイコンがTLの場合、`tl-switch-notes.md` の注意（枝番予約番号・楽天/一休/Trip.com予約データの事前ダウンロード）を反映したか

## よくある質問への対応

- 「○○（サイト名）って事前に何かいるの?」→ `site-requirements.md` の該当サイトを引いて答える
- 「導入日を○/○にしたいが間に合うか?」→ 申請期限早見表から最長リードタイムのサイトを特定して逆算し、間に合うか判定する
- 「当日は何時間くらいかかる? 何をする?」→ 当日29ステップのうち該当分を要約して答える
