## 5. 導入当日にやること（8/26(水) チェックリスト）

流れ: **売止 → TLから予約データ確保 → 切替 → 連携確認 → 部屋取得・紐付け → 予約取込 → 料金 → PMS連動 → 確認 → 再販売**

- □ TLリンカーンから全サイトを売止する

- □ 各サイトのゲスト画面（宿泊者から見える画面）で売止を確認する
  ※じゃらんnet・ベストリザーブ・宿ぷらざは事前接続済み（すでに手間いらず経由で在庫管理中）のため売止対象外

### 5-2. チャネルマネージャー切替（管理画面操作）

- □ **Booking.com**: アカウント（人型アイコン）＞コネクティビティ・プロバイダー＞「プロバイダーを切り替える」＞ Temairazu を検索・選択し契約手続き（既存プロバイダーとの連動は切替完了まで維持されます。切替後は管理画面で料金・空室が最新か必ず確認）
- □ **Expedia**: 三＞客室と料金＞サイトコントローラー設定＞認証＞変更＞ Temairazu 登録。**「料金と在庫」と「予約」の両方**を TEMAIRAZU に変更
- □ **Agoda**: 管理画面で利用するサイトコントローラーを「TEMAIRAZU」に設定し申請（最後に「保存する」→「success」表示でOK）
- □ **Airbnb**: アカウント紐付け操作を行う（設定＞予約サイト設定＞Airbnb アカウント設定＞「Airbnbをログアウト」→ログアウト完了→「Airbnbとつながる」→ログイン→画面の指示に従い許可→アカウント設定に「紐付け済み」表示を確認）
- □ **Trip.com(NEW)**: Trip.com に問い合わせて「手間いらずとの連動準備ができているか」を確認する

### 5-5. 部屋取得・紐付け

- □ 部屋プランを取得する（ツール＞各種ツール＞部屋・プラン取得、または各サイトの部屋プラン一覧から）
- □ 部屋を紐付ける（設定＞予約サイト設定＞該当サイト 部屋プラン一覧。最大提供部屋数・提供限界部屋数を設定。変更後は必ず在庫のリフレッシュ更新）
- □ 紐付けを確認する（設定＞基本設定＞部屋マスタ＞画面最下部「予約サイト部屋一括管理」）

### 5-6. 予約の取込（PMS一時停止 → 取込 → 出力済設定）

- □ 当日切替サイトを**一時的にPMSに出力しない**設定にする（PMS項目設定＞エージェント情報＞各OTA「出力しない」。可能なら事前にPMS会社に「連絡するまで一時的に情報を取りに来ないでほしい」と伝えておく）
- □ 更新設定の予約取得にチェックを入れる（設定＞更新設定＞予約サイトを選択し予約取得設定「取得する」＞設定する）
- □ 過去の予約情報を取得する（ツール＞各種ツール＞過去の予約情報取得＞本日以降の予約を一括取得＞実行。※先に各サイトのアカウント設定で料金在庫管理期間の設定が必要）
  - **Booking.com / Expedia / Airbnb**: 一括取得可（制限は「6. サイト別の注意点」参照）
  - **Agoda**: 一括取得ではなく**予約日指定**で取得（条件: 予約日、取得期間: 操作当日から遡って740日前〜90日後、**90日ずつ分割**して複数回実行。約2年前までの予約をどこまで取り込むかは状況に応じて判断）
  - **楽天トラベル・一休.com・Trip.com(NEW)**: 過去予約取得**不可** → 事前相談済みのアップロード対応（アップロードは部屋の紐付け設定後に実施）
  - ※アップロードと取得の両方を行う場合、**一休の予約反映を先に**行ってから他サイトの過去予約取得を行う（順序を誤ると在庫が戻りオーバーブッキングのリスク）— 段取りは手間いらず側と当日確認
- □ 料金グループ or プラングループへ紐付け・料金設定を行う（グループを利用しない場合はプラン料金設定。マニュアル: ヘルプ＞マニュアル＞4.料金設定）
- □ **PMSデータ出力済設定**を行う（オプション＞PMS項目設定＞データ再出力/出力済設定 → ①アクション「出力済設定」②対象データ「宿泊日で指定」③宿泊日選択 ④対象予約サイト選択 ⑤設定する）。**完了後、出力設定を「出力する」に戻す**
- □ 料金を確認する（設定＞予約サイト設定＞部屋プラン一覧＞プラン名クリックで設定料金を確認）

### 5-7. PMS連動再開・最終確認・再販売

- □ **PMS会社に連絡**し、手間いらずと連動を再開する（1way連携: PMSに予約情報を取りに来てもらうよう依頼）
- □ 導入作業中に発生した変更・キャンセルを各サイト管理画面で確認する（必要に応じてPMSデータ再出力設定）
- □ 在庫を調整する（最終在庫数の登録・確認。楽天・一休・Trip.com(NEW) などアップロード対象分や、電話等のオンハンド予約分を反映）
- □ 更新設定を行う（設定＞更新設定 → ①在庫更新 ②料金更新 ③予約サイトにチェック ④設定する）
- □ リフレッシュ更新を行う（ツール＞各種ツール＞リフレッシュ更新 → 部屋在庫を更新（全サイト・全月）を実行 → プラン料金を更新を実行）
- □ 各サイト管理画面で在庫・料金を確認し再販売する（**直近1か所と12か月後1か所**をサイト管理画面と手間いらずで照合・目視確認 → 問題なければ再販売）
- □ ゲスト画面で販売状態・在庫・料金を確認する（直近1か所と12か月後1か所）

## 6. サイト別の注意点

### 楽天トラベル
- R-connect は「楽天トラベル管理画面」と「手間いらず画面」の**両方からの申請**が必要です。
- 通常は当日正午までの申請で 15〜17時に連携完了。**午前中など時間指定がある場合は前日 8/25(火) 11:50 まで**に両申請を完了させてください。
- R-connect 連携後は導入時の過去予約取得ができません（連携開始以降に発生した予約は取得可能）。→ TLからのデータダウンロード＋アップロード対応。
- TLリンカーンへの解約連絡時に「導入希望日時に間に合うように楽天トラベルと解約したい」と必ず強調してください。
- アカウント設定の「未確認の予約(確認)を行う」: R-connect 利用中は影響ありません。

### じゃらんnet
- 事前接続可・申請不要。導入前に部屋取得〜過去予約取得まで完了できます。
- 当日の**予約取得高速化設定は必須**です（設定＞基本設定＞予約取得高速化）。初回設定時は転送を必ず「利用する」にし、じゃらん管理画面（基本情報設定＞予約基本設定（通知管理））で通知先メールアドレスの設定・送信テストを行ってください。予約通知方法がFAXかメールかで手順が異なります。

### 一休.com
- **8/24(月) 18:00 までの連動申請が必須**（2営業日前の期限）。
- 過去予約取得不可 → TLからのデータ確保＋手間いらず側アップロード対応（TL切替の場合は特別対応となるため必ず事前相談）。
- 予約取得高速化には予約データダウンロードサービスの契約が必要です。
- 予約データダウンロードサービスを利用しない場合、取得予約は分割・ダミー予約番号・個人情報なしなど大きな制約があります（アカウント設定のヘルプ参照）。

### Booking.com
- 過去予約取得は「宿泊日が本日以降のキャンセルでない予約（オンハンド予約）」がすべて取得されますが、**メールアドレス・住所・電話番号・備考・宿泊者氏名・支払方法（「不明」になる）等は取得されません**。予約番号指定で取得すればこれらも取得可能です。→ TL売止後にBooking.comの予約データをダウンロードし、予約番号指定取込を推奨。
- アカウント設定「**予約情報のプラン名に1泊目のレート名を設定する**」にチェックを入れないと予約のプラン名が空欄になり、**PMSによってはエラーで予約が反映されない**場合があります（1way連携のため要確認）。
- 「部屋タイプ単位で予約を取得する」は一度ONにすると元に戻せません。設定するかどうか事前に判断してください。
- **TL切替特有**: Booking.com の変更・キャンセル情報は予約番号に枝番（例: ●●●●-1）が付いてPMSに入るため、TL利用時に入った元予約がPMS上に残る事象が起こり得ます。当日の取込一覧を見て、手間いらずとPMSを見比べて確認してください（TL時代の予約が消化されれば不要になります）。

### Expedia
- 管理画面切替時は「**料金と在庫**」と「**予約**」の両方を TEMAIRAZU に変更してください（片方だけだと連携不完全）。
- 過去予約取得では「住所」が取得できません。条件は予約日・宿泊日・予約番号のみ。宿泊日指定の場合はチェックアウト日を含むように設定。一括取得はチェックアウト日ベースのため、管理期間の境目にかかる予約は個別条件で再取得してください。
- Base Allocation 契約がある場合、その在庫分は手間いらずで管理できません（アカウント設定「在庫更新設定」参照）。

### Agoda
- 過去予約取得は一括取得ボタンではなく、**条件: 予約日／取得期間: 当日から遡って740日前〜90日後を90日ずつ分割**して複数回実行します。
- 管理画面切替は最後に「保存する」→「success」表示を確認。

### Trip.com(NEW)
- **手間いらず側とTrip.com管理画面側の両方の申請が完了して初めて接続**されます。リードタイム不定のため、導入日決定後すぐに動いてください。
- 過去予約取得不可 → TLからのデータ確保＋事前相談。
- 予約情報は初期設定では「部分取得」。全取得（予約詳細の確認に必要）はダウンロード通知サービスの契約が必要で、1予約あたり38円（税抜）かかります。一度部分取得した予約を後から全取得し直すことはできません。

### Airbnb
- **スマートプライシング利用中の場合、手間いらず連携前に必ず解除**してください（連携後は解除不可になります）。
- 手間いらずの1アカウントに紐付けられる Airbnb アカウントは1つのみ。アカウント内のリスティングは**この施設のもののみ**にしてください（複数施設分があると予約が正しく取り込めません）。
- メールアドレス認証・電話番号認証が完了している必要があります。チームアカウント、他の連携済みアプリがあるアカウントは紐付けできません。
- 過去予約取得は、条件指定に関わらず宿泊日が本日以降のオンハンド予約をすべて取得します。TLで共通在庫運用だった場合は取得不可。
- 料金在庫管理期間は固定で変更できません。

### ベストリザーブ・宿ぷらざ
- 事前接続可・申請不要。導入前に準備を完了できます。
- **TLリンカーンで共通在庫運用していた場合は過去予約取得不可**（要確認事項 #4）。その場合は事前に予約データを控えておいてください。
