# 個別案件向け導入手順書テンプレート

施設担当者に渡す手順書は、必ずこの構成で作成する。「自分の施設は何を・いつ・どの順でやればよいか」が一目でわかることがゴール。
一般論の羅列ではなく、**その施設の連携サイト名・PMS名・日付を埋め込んだ具体的な文書**にする。

---

# 【施設名】様 手間いらず導入手順書

作成日: YYYY-MM-DD ／ 導入予定日: YYYY-MM-DD（切替時間があれば明記）

## 0. ⚠ 要確認事項

ヒアリングで未確定だった項目・施設側で確認が必要な項目を冒頭に表でまとめる（確認事項＋なぜ必要かの2列）。全項目確定済みならこのセクションは省略可。

## 1. 導入概要

| 項目 | 内容 |
|---|---|
| 施設名 | |
| 導入予定日（切替日） | |
| 現在のサイトコントローラー | （新規導入の場合は「なし（新規）」） |
| PMS | （なし/PMS名。連携方式: 1way/2way） |
| 連携予定サイト数 | ○サイト |

## 2. 連携サイトの分類

その施設の連携サイトを `site-requirements.md` に基づき分類した表。**この表が手順書の心臓部**。

| サイト名 | 種別 | 事前接続 | 申請 | 申請期限（逆算日付） | 過去予約取得 |
|---|---|---|---|---|---|
| 楽天トラベル | OTA | 否 | 両方申請（R-connect） | ○/○ 11:50まで | 不可 |
| … | | | | | |

分類のポイント:
- **事前接続「可」グループ** → 導入前に部屋取得・紐付け・過去予約取得まで済ませられる
- **事前接続「否」グループ** → 導入当日に切替・取得を行う
- **過去予約取得「不可」のサイト** → 導入前に現サイトコントローラーから予約データをダウンロードしておく必要がある（この表の下に対象サイト名を明記して注意書きする）

## 3. スケジュール（導入日からの逆算）

導入日を起点に、期限のあるタスクを日付順に並べる。営業日ベースの期限（一休=2営業日前18時など）は**具体的な日付に変換**して書く。土日祝は営業日に含めない（祝日が不明な場合はその旨注記）。

| 期限 | やること | 担当 |
|---|---|---|
| ○/○（○営業日前） | 一休.com 連動申請（手間いらず画面から） | 施設 |
| … | | |
| 導入日 ○/○ | 当日作業（セクション5） | 施設・手間いらず |

## 4. 導入前にやること（チェックリスト）

`master-checklist.md` フェーズ1から該当ステップのみ。各項目は「□ チェックボックス＋作業名＋手間いらず画面の操作パス＋この施設固有の補足」の形式。
サイト固有の申請手順（楽天R-connect、JTB、ANAなど）は該当サイトがある場合のみ、そのサイト名を出して具体的に書く。

## 5. 導入当日にやること（チェックリスト）

`master-checklist.md` フェーズ2から該当ステップのみ。売止→切替→取得→紐付け→料金→確認→再販売 の流れがわかるよう、時系列順に。
Booking.com/Expedia/Agodaの管理画面切替手順は、その施設が使うサイトの分だけ記載。

## 6. サイト別の注意点

その施設が使うサイトのうち、注意事項があるものだけを抜粋（`site-requirements.md`・`ota-account-settings.md` から）。使わないサイトの情報は載せない。

## 7. 困ったときの連絡先

- 手間いらずカスタマーセンター（申請・連携状況の確認）
- 手間いらず営業担当
- 各OTAサポート（切替関連で問合せが必要なサイトのみ列挙）

## 出力形式の使い分け

- **既定**: 上記構成のMarkdown → ユーザーの指定に応じて Excel（xlsx Skill / チェックリスト形式・シート分割: 概要/スケジュール/導入前/当日/サイト別注意）、Word（docx Skill）、HTML に変換する
- 施設担当者に印刷して渡す想定なら docx か xlsx を推奨
- チェックボックス列（□）を必ず付け、担当者が進捗を書き込めるようにする
