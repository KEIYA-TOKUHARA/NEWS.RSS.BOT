# TLリンカーン等からの切替時の注意点・社内向け補足

前サイトコントローラーがTLリンカーン（TL）の場合の特有の注意点と、導入当日の予約データ移行に関する社内ノウハウ。

## TL切替 注意事項

【手間いらず上での予約状態に関して】
  事象：過去予約情報取得(TL上に入っている先々の予約情報を手間いらずに取り込む)を行ったが、変更情報が手間いらず上にない。なぜか？
  理由：変更情報は、一回でも手間いらず側に予約情報を取得していないと発生しないです。
  過去予約情報取得で初めて取得したのであれば全て「新規」となります

【ANA,booking.com,ダイレクトイン経由変更・キャンセル情報の予約番号に関して】
 ダイレクトイン、ANA、booking.comの予約変更キャンセル情報は、手間いらずに入ってくる時点で予約番号に枝番(●●●●-1)が降られる仕様になっております。
 その為、TL利用時にPMSに入った予約は予約番号(●●●●)のみだが、その予約に対してキャンセルや変更情報が入ったら予約番号のお尻に「●●●●-1」という形で枝番がふられてPMSに入ってくるので、元の予約情報が消えずに残っている事象が発生する可能性があります。
 ≪例：TL時に入った予約が手間いらず切り替え後にキャンセルになった場合、PMS上での予約番号が下記の2つ存在する≫
 13590(TL時に入った予約情報番号）
 14565 (キャンセル情報番号) 
 
 〈対応方法例〉PMSがDynalutionの場合
対策としては、PMS上での取り込み確認表（帳票）という、その日に取り込んだ情報一覧を見てANA,booking.com,ダイレクトイン経由の変更情報とキャンセル情報があれば、お手数ですが、手間いらずとPMSを見比べて頂く方法がございます。
 また、TL利用時の予約がなくなれば、このような事はしなくてよくなります。


## 導入当日の予約データ移行（社内向けノウハウ）

- 過去の予約情報取得不可の一部予約サイト(Trip.com、Trip.com(NEW)、一休.com、楽天トラベル)とBooking.comの予約情報を前サイトコントローラーからダウンロード / ≪TLからの切り替えの場合≫
  ・TL上で売止後に楽天トラベルの予約情報をTLからダウンロードする
  ・Trip.com,Trip.com(NEW),一休.comについては、事前に入江さんに予約情報のアップロード対応を行っていただきたい旨の相談をする。
  ・TL上で売止後にTL上で入江さんに対応希望の予約情報をサイト毎にダウンロードする
  ・ダウンロードしたデータを入江さんに送る
  ※予約情報のアップロードは部屋の紐付け設定後に行っていただく必要がある
  
  ※Booking.com
  Booking.comは予約番号指定以外での過去の予約情報取得を行うと支払い方法が「不明」で取得される
  支払い方法「不明」での取得がどうしても嫌という場合は、管理ツールから予約アップロードを行う必要がある。
  
  ≪ねっぱん、らく通、エアホストからの切り替えの場合≫
  前サイトコントローラーで売止後に一休.comと楽天トラベルとBooking.comの予約情報を前サイトコントローラーからダウンロードする
  ※前サイトコントローラーで一休.comの予約ダウンロードサービスを利用していた場合は、手間いらず管理ツール上でアップロードが可能

- 過去の予約情報取得　一休予約アップロード / ※TLからの乗換の場合は対応できない。
  (事前に入江さんに相談している場合は、入江さんにデータを送りアップロードしていただく)
  
  【一休予約アップロードの手順】
  ※あらかじめ該当予約の予約番号のリストを作成しておいていただく。
  ①最大受付予約数を設定しておく。
  ②手間いらず管理ツール＞サポートツール＞予約データアップロード＞一休予約CSVアップロード
  ＞手間いらずホテルID下4桁(82から始まるホテルIDの場合は頭に1をつける)
  ＞「テンプレートのダウンロード」をクリックして、手間いらずのホテルIDと予約番号をExcel上に入力
  ③手間いらず管理ツール＞サポートツール＞予約データアップロード＞一休予約CSVアップロード
  ＞手間いらずホテルID下4桁(82から始まるホテルIDの場合は頭に1をつける)
  ＞アップロードする
  
  ※アップロードが完了したかは管理ツール上でも確認できない。
  予約者検索で確認いただく。 / 【アップロードの仕様】
  一休のアップロード処理：新規→キャンセルと順々に取得する仕様
  
  【一休予約アップロードの条件】
  ①手間いらず管理ツール上でAPIパスが設定されている(ヘルプから申請いただきCS側で設定完了)
  ②予約ダウンロードサービスを利用している
  
  【一休予約アップロードの注意事項】
  ・手間いらずMINIは対象外(手間いらず.NET→miniに変更する場合は対応可能)
  ・部屋数が少ない、または少ない部屋タイプがある施設は事前に最大受付予約数を設定しておく
  ・一休予約アップロードを行ってから、他サイトの過去の予約情報取得操作をする(一休と楽天のアップロード両方行いたい場合も一休から先に行う)
  一休予約アップロードは新規予約情報＞変更情報＞キャンセル情報の順番で反映するため、先に他サイトの過去の予約情報取得してしますと一休のキャンセル情報を取得した際に在庫が1戻り、OBリスクになるため。
  (例)基本在庫が1部屋の場合
  他サイトで過去の予約情報取得し、在庫0/予約1になる。
  一休予約アップロードを行い、一休の新規予約が反映し在庫0/予約2になる。
  一休のキャンセル情報が反映され、在庫1/予約1になりOBリスクになる。
  ※一休の変更情報がある場合もOBリスクになるので、一休予約アップロードを行ってから他サイトの過去の予約情報取得操作をする

  そのため、手間いらず管理ツール上から予約をアップロード操作していただく必要がある。
  【手順】
  ※あらかじめ該当予約の予約番号のリストを作成しておいていただく。
  ①手間いらず管理ツール＞サポートツール＞予約データアップロード＞楽天予約CSVアップロード
  ＞ホテルID欄に手間いらずホテルID下4桁(82から始まるホテルIDの場合は頭に1をつける)を入力し「施設検索」をクリック
  ＞「テンプレートのダウンロード」をクリックして、手間いらずのホテルIDと予約番号をExcel上に入力
  ②手間いらず管理ツール＞サポートツール＞予約データアップロード＞楽天予約CSVアップロード
  ＞アップロードする / 【注意事項】
  ①楽天グローバルプラットフォームと楽天トラベルを統合されている場合
  統合前に楽天グローバルプラットフォームで発生した予約情報はアップロード機能でも取り込むことはできない。
  ※楽天グローバルプラットフォーム単体で手間いらずと連携の場合は
  過去の予約情報取得操作で楽天グローバルプラットフォームの予約を取り込むことは可能。
  
  ②楽天トラベルの予約アップロードは最新の予約状態のみアップロードする。
  そのため、変更情報は変更として反映される
  
  【取得対象となるの予約】
  ①楽天トラベル国内の予約(RYで始まる予約)
  ②デイユースの予約(DUで始まる予約)
  ③パッケージの予約(WSで始まる予約)
  ④インバウントの予約(数字だけの予約)
  ※④について、現状統合前の楽天GPの予約も取り込まれる。取り込まないようBacklog登録済（R-connectを繋いだら変更やキャンセルが取得できなくなるため）。以下対応が完了したら、統合後の予約のみ取得することとなる。
  https://temairazu.backlog.com/view/TMZREQ-1282
  
  【加工が必要な予約番号】
  楽天の過去予約情報取得時、お客様から共有された予約番号が下記の形式で共有された場合は、加工して取り込んでください。
  
  例：加工前
  RJ22461143516320459WS246114451638559_1
  
  例：加工後
  WS246114451638559
  
  ※末尾の枝番（「_1」など）は削除してください。
  ※先頭の不要な文字列は除き、「WS」から始まる予約番号のみを転記してください。

- 過去の予約情報取得　Booking.comの予約アップロード / 【手順】
  ※あらかじめ該当予約の予約番号のリストを作成しておいていただく。
  ①手間いらず管理ツール＞サポートツール＞予約データアップロード＞Booking.com予約CSVアップロード
  ＞ホテルID欄に手間いらずホテルID下4桁(82から始まるホテルIDの場合は頭に1をつける)を入力し「施設検索」をクリック
  ＞「テンプレートのダウンロード」をクリックして、手間いらずのホテルIDと予約番号をExcel上に入力
  ②手間いらず管理ツール＞サポートツール＞予約データアップロード＞Booking.com予約CSVアップロード
  ＞アップロードする / 【注意事項】
  ①Excelデータ上で入力する予約番号は、枝番のつかないBooking.com管理画面上の予約番号を入力する。
  ②キャンセル済みのものをアップロードすると取り込まれていないキャンセル取得のアラートが表示されます。
  ③管理ツールから予約アップロードを行うと、予約番号指定で過去予約取得をするのと同じ動作になります。(支払い方法などの取得が可能です）
  ④過去予約取得の画面操作とほぼ同じ動作をするので、数が多いとアップロードしてから反映されるまでに時間がかかります。
  また、予約が取り終わるまで過去予約取得画面の操作ができない（直近の操作の予約取得処理が云々のアラートが出ます）ので注意してください。
